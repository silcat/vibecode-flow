## 2026-06-02：加强强制性日志记录规则

### 上下文

模板有 `docs/logs/` 和 `00-log-writing-guide.md`，但 AGENTS.md 只说"保持日志简短、带日期、仅追加"而没有强制性触发条件。在实践中（nop-chaos-flux），AI 从不写日志因为没有条件强制它。nop-chaos-flux 不得不在 AGENTS.md 中加入了自己的"文档维护"章节，带有显式强制性触发条件、验证清单和全绿基线记录规则。

### 决策

- 更新 AGENTS.md 运营规则 7：添加强制性触发条件"完成任何重要的代码变更后，必须更新每日开发日志"
- 向 AGENTS.md 添加 `文档维护` 章节，包含两个强制条目（日志更新 + 所有者文档更新）和全绿基线记录规则
- 将 `docs/logs/00-log-writing-guide.md` 从 19 行骨架扩展为完整指南，包含用途、规则（6 项）、路径约定、条目格式示例和分步添加新条目说明
- 向 `START-HERE-after-copy.md` 必做清单添加日志目录初始化步骤

### 理由

没有强制性触发条件和具体格式指南，日志规则对 AI 代理是不可见的。模板有目录结构和占位符指南，但 AGENTS.md 和指南都没有告诉代理何时或如何写条目。nop-chaos-flux 证明了带有 MUST 级触发条件和全绿记录规则的"文档维护"章节确实让日志记录发生。

### 后果

复制后的项目从一开始就有可执行的日志规则。扩展后的 `00-log-writing-guide.md` 提供了足够的格式细节，代理可以写出结构良好的条目而不必猜测。START-HERE 清单确保日志目录结构在第一次编码会话前就位。

## 2026-05-29：添加可复用工程技能和可选工具工作区

### 上下文

模板现在包含更广泛的可复用工程表面：Bug 诊断、代码质量审计、重构发现、重构执行、根级别文本文件默认值，以及用于通用检查的仓库本地 `tools/` 工作区。

### 决策

- 添加 `docs/skills/bug-diagnosis-prompt.md`
- 添加 `docs/skills/code-quality-audit-prompt.md`
- 添加 `docs/skills/code-refactor-discovery-prompt.md`
- 添加 `docs/skills/code-refactor-prompt.md`
- 更新 `docs/skills/README.md`
- 添加 `.editorconfig`、`.gitattributes` 和 `.gitignore`
- 添加 `tools/` 作为可选 pnpm 子项目，用于可复用的仓库本地工具

### 理由

此变更是因为模板已经定义了文档驱动的工作流，但缺乏三种在路由之后反复出现的常见执行模式的可复用方法：证明根因、审计变更代码的真实风险，以及在不大静默改变行为的情况下重构代码。

仓库还需要为复制后的项目提供一个小型默认质量基线。根级别文本规范化减少了可避免的 diff，同时将基于 Node 的工具保留在 `tools/` 内保持了模板的跨技术栈姿态，而非将仓库根变成纯 Node 项目。

### 后果

复制后的项目可以立即采用更广泛的可复用工程方法，并且有一个现成的地方来生长轻量级仓库本地检查，而无需将整个模板耦合到单一运行时栈。

## 2026-05-29：添加索引路由审计技能

### 上下文

现有审计技能涵盖文档质量和计划/决策审计，但没有验证索引树（`docs/index.md` + 各目录 README）是否确实将读者路由到正确位置。

### 决策

- 添加 `docs/skills/index-routing-audit-prompt.md`

### 理由

此变更是因为路由质量是模板的反复出现风险：复制后的项目可以有正确的所有者文档，但仍然未能引导代理和维护者到正确的下一个产物。

路由失败通常是情境性的：索引入口在技术上可以是正确的但仍然对特定角色失败。简单检查清单会遗漏这一点。此提示词使用三层——覆盖表、基于角色的路由测试、结构检查——使得机械正确性和情境可及性都得到评估。
