# 文档漂移记录

## 用途

记录所有者文档与活代码之间已发现的不一致。每条记录是一个待裁决或已裁决的漂移。

此文件是 `project-context.md` 全局新鲜度和 `codebase-map.md` 行级置信度的**证据源**。

## 分类

| 分类 | 含义 |
|------|------|
| 实施漂移 | 代码偏离了正确的文档——应改代码以匹配文档 |
| 文档漂移 | 文档未随代码更新——应改文档以匹配代码 |
| 有意遗留 | 双方都准确，不一致是已知的有意设计决策 |

## 状态

| 状态 | 含义 |
|------|------|
| 未处理 | 已发现，尚未裁决 |
| 已确认(不修) | 人类确认此为有意行为，不计划修改 |
| 已创建计划 | 已创建 work item / plan 来解决 |
| 已修复 | 代码或文档已更新，不一致已消除 |

## 规则

### 状态流转

```
发现不一致
    │
    ▼
 未处理 ───────────────┐
    │                   │
    ▼                   ▼
 分类裁决           已确认(不修) ←── 人类判定为有意行为
    │
    ├── 文档漂移 → AI 可修文档（非保护区）
    ├── 实施漂移 → 需判断改代码的风险等级
    └── 有意遗留 → 已确认(不修)
    │
    ▼
 已创建计划 ←── 修复涉及保护区 / 跨模块 / >5 文件
    │
    ▼
 已修复
```

### 谁做什么

| 步骤 | 谁 | 动作 |
|------|-----|------|
| 发现 | AI 或人 | 新增一行，状态 `未处理`，描述留空分类 |
| 分类裁决 | **人类** | 判定 `实施漂移` / `文档漂移` / `有意遗留`。AI 可提议但需人类确认（分类涉及"哪个才是对的"的价值判断） |
| 小修（文档漂移、非保护区、≤5 文件） | AI | 直接修复文档/代码，完成后状态改为 `已修复` |
| 大修（保护区、跨模块、>5 文件、实施漂移） | AI | 创建 plan → 状态改为 `已创建计划`，关联列填 plan 名 |
| 有意遗留 | **人类** | 状态改为 `已确认(不修)` |

### 其他规则

- 发现不一致时新增一行，状态 `未处理`
- 裁决后更新分类和状态，不删除行
- `source-of-truth-and-precedence.md` 的 Stale-Docs Mode 触发后，漂移分类必须记录到此文件
- 所有 `未处理` 条目 ≥1 时，对应文件的置信度为 `low`，全局新鲜度至少为 `partially stale`
- 所有条目均为 `已修复` 或 `已确认(不修)` 后，置信度可升回，全局新鲜度可考虑升回（**需人类确认**）
