# 开发日志编写指南

开发日志条目按日期组织，每天一个文件。

## 用途

每条每日日志捕获简短带日期的笔记，内容涉及：

- 添加或更新了什么文档
- 做了什么设计决策
- 计划下一步做什么
- 以后需要记住但不属于正式架构文档的小型上下文

## 规则

- **每天一个文件** — 同一天的所有工作写入同一文件
- **追加新条目** — 在文件顶部添加新的 `### YYYY-MM-DD` 节（倒序）
- **保持条目简短** — 优先使用要点列表，链接到主文档或代码路径
- **不是真源** — 这是轻量上下文，不是规范架构
- **链接到真实文档** — 引用设计决策时，链接到架构文档或代码路径
- **将日志文件视为仅追加历史** — 文件长度本身不是缺陷；不要仅因为每日日志增长到超出活跃文档大小指南就标记问题

## 路径约定

- `docs/logs/{年份}/{月}-{日}.md`

## 条目格式

```markdown
# 开发日志 - YYYY-MM-DD

### YYYY-MM-DD

- 简要描述发生了什么。
- 链接到文档或代码路径：`docs/baseline/architecture/xxx.md` 或 `src/foo/bar.ts:42`
- 关键决策：……
- 下一步：……
```

## 添加新条目

1. 打开 `docs/logs/{年份}/{月}-{日}.md`（如不存在则创建）
2. 在顶部、任何已有条目之前添加 `### YYYY-MM-DD` 节
3. 撰写新的要点
4. 如果当天已有更早的条目，在空行分隔符后追加
