# 模块边界

## 用途

定义 `<项目名称>` 的主要代码所有权边界。

当设计争议反复出现且取决于模块归属时，答案写在这里，不要在聊天中重复辩论。

此文件只管架构级耦合规则（本项目模块之间、模块与基础设施之间）。jar 包依赖查 pom.xml，不写在这里。

模块内部的包级分层和层间依赖规则见 module-internals.md。

## 更新触发条件

以下情况才需要改本文件：

- 新增/删除一个模块（单体）或服务（微服务）
- 现有模块/服务的职责范围发生变化
- 依赖方向新增合法路径，或需要封堵一种滥用
- 数据所有权发生转移
- 端口分配变化
