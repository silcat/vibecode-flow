# 关键业务流程索引

## 用途

本文件是项目**业务主流程**的路由表——完整的用户可见业务场景，串起多个模块协同完成一个业务结果。

具体时序图和步骤表存放在发起方模块的 `docs/flows/` 下。技术子步骤（如"如何调微信支付 API"）属于 `docs/skills/tech/`，不在此记录。

## 什么算关键业务流程

判断标准：**是不是一个完整的业务场景**。

需要 flow：

- 支付流程（下单→支付→回调→改状态→通知）
- 优惠券流程（发放→领取→使用→过期）
- 退款流程、对账流程、用户注册流程……

不需要 flow：

- 技术子步骤（"调微信支付统一下单 API"——这是 tech 技能）
- 单服务内部逻辑
- 纯技术运维（健康检查、日志轮转）

一句话：**业务人员能叫出名字的端到端场景，就是关键业务流程**。

## 创建时机

| 阶段 | 动作 |
|------|------|
| ⑧ 编写计划 | 计划已预见的业务主流程 → **创建** flow，随计划产出 |
| ⑩ 实施验证 | 代码写完 → **对账**：已有 flow 对照更新，未预见的新业务主流程补建 |

## 维护规则

- 新增业务主流程：在发起方模块下创建 `docs/flows/<流程>.md`，本文件新增一行
- 删除流程：删除对应流程文件，本文件删除对应行
- 单模块内部流程不在此记录
- 修改跨模块通信代码后检查命中流程的边界列，判断是否需更新

## 触发决策

修改代码后，按以下决策树判断是否需要更新流程文件：

```
是否跨模块边界？
  ├─ 否 → 不动 flow
  └─ 是 → 是否改变了调用序列、通道、或失败策略？
            ├─ 否 → 不动 flow
            └─ 是 → 是 Bug（代码偏离了 flow）还是设计变更（flow 本身要改）？
                      ├─ Bug → 修代码，不动 flow
                      └─ 设计变更 → 更新 flow
```

**跨模块边界的识别方式**：搜索 `docs/flows/` 下所有流程文件的"边界"列，若本次修改的 Feign 接口/方法、topic 名、或网关路由规则命中，即为跨模块边界。
