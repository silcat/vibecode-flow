# 实施指南

## 用途

本指南收录 AI 和人类的日常编码期望。

## 核心规则

- 优先最小的正确变更
- 遵循现有模式再发明新抽象
- 保持状态所有权显式
- 除非活跃需求明确允许，避免仅用于 demo 的占位符
- 当 Bug 或契约可能静默回归时添加测试
- 不要将代码级技术细节放入计划文件，除非它们为范围、证明或契约推理所必需
- 默认不注释；仅在局部约束容易被误读时添加少量高价值注释

## 审查视角

审查工作时，检查：

- 边界违规
- 未写入文件的隐藏假设
- 仅基于聊天声明的虚假完成（未实际运行验证命令）
- 对用户可见行为缺少验证

## 协作规则

如果重复的指令不断在聊天中重新出现，将其提升到 `AGENTS.md`、`docs/baseline/architecture/` 或 `docs/references/`。

如果重复的审查模式持续发现相同类别的问题，将其提升为 `docs/skills/` 或 `docs/work/<分支>/`。

如果在此之后相同的缺陷模式仍复发，评估是否应进一步将其提升为启发式脚本、静态检查、Lint 规则、CI 守卫或 codemod。优先轻量级检查，并根据复制后项目的真实约定、命名模式和误报容忍度进行调优。
