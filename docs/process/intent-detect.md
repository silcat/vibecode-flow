# 意图检测协议

在路由用户请求到具体流程之前，先对请求的模糊度评分，按模糊程度选择三级响应策略（静默路由 / 摘要确认 / 完整澄清），再选定路由。目标是问对的问题、在合适的时机，不给清晰的请求增加摩擦。

## 信号评分

每个信号命中记 +1 分。求和得模糊度分数。

| # | 信号 | +1 条件 |
|---|------|---------|
| 1 | 范围模糊 | 请求涉及多个功能/模块但未指名（仅供 Tier 判定，复杂度路由交由流程内部阶段判定） |
| 2 | 无明确路径 | 未提及文件名、包名、功能名 |
| 3 | 多重意图 | 可能是修复/功能/重构/问题中的多种 |
| 4 | 首次交互 | 当前会话无已建立的工作流上下文 |
| 5 | 无伴随输入文件 | docs/work/ 中无对应材料 |
| 6 | 与设计基线潜在冲突 | 请求与 project-context.md 或 standards/ 已记录基线矛盾 |

## Tier 阈值与响应

| 分数 | Tier | 响应 |
|------|------|------|
| 0–1 | Tier 0 | 静默路由，直接进入流程 |
| 2–3 | Tier 1 | 展示路由摘要，等待用户确认后路由 |
| 4+ | Tier 2 | 完整澄清检查点，多选问题，等待回答后路由 |

## 自动跳过条件

以下条件命中时，跳过评分直接按 Tier 0 路由：

- 用户说"继续"/"go"/"做吧" 或类似继续性短语（结合 registry 活跃计划恢复执行）
- 琐碎修复（单文件 + <15 行 + 无契约变更）
- 纯信息问题（"XX 是什么？""YY 怎么工作？"），且路由目标唯一明确
- 显式模式命令

## 轻量研究通

Tier 1 / Tier 2 在展示摘要或提问前，先执行轻量研究通（主线程内完成，不委托子代理）：

预算：3–5 次文件读取，30 秒内。

检查项：
1. 活跃计划扫描 — `docs/work/registry.md` 中是否有活跃计划
2. 近期 git 状态 — 是否有与请求相关的未提交变更
3. 若请求指明了具体文件或包，快速读取该文件
4. 上下文路由表 — `docs/baseline/context/README.md` 匹配关键词到上下文域

目的：让 Tier 1 摘要和 Tier 2 问题占位符填入具体值，而非泛泛文本。

## Tier 0：静默路由

分数 0–1 或自动跳过触发。不增加任何用户交互。

直接按路由表选定路由并进入对应流程。不展示路由摘要，不请求确认。

## Tier 1：路由摘要 + 确认暂停

执行轻量研究通后，展示：

```
路由：[检测到的意图] → [目标流程]
范围：[我认为你想改什么]
计划：[若发现已有计划则列出，否则 "新工作"]
```

**等待**用户下一条消息后再路由。不在同一回复中路由，不说"我默认继续除非你纠正"。

不提问（与 Tier 2 不同），但给用户一个在进入流程前纠正路由的机会。

- 用户确认（"对"/"可以"/"go"）或发送继续性消息 → 进入路由
- 用户纠正（"不是，我意思是 X"）→ 用新信息重新评分，重新路由

## Tier 2：完整澄清检查点

执行轻量研究通后，从问题类别菜单中选 2–4 个类别提问。仅一个类别模糊时只问一个问题，不凑数。

### 问题类别菜单

| 类别 | 模板 |
|------|------|
| 范围 | "涉及哪些区域？[A] 仅 {X} [B] {X} 和 {Y} [C] 整个 {功能}" |
| 方向 | "处理方式？[A] 快速修复 [B] 正式重构 [C] 你来决定" |
| 约束 | "限制条件？[A] 不能动 {Z} [B] 需向后兼容 [C] 无" |
| 验收 | "完成标准？[A] 测试通过 [B] 已部署 [C] 已代码审查" |
| 上下文 | "关联已有工作？[A] 关联 {计划 X} [B] 新工作 [C] 不确定" |
| 优先级 | "优先级？[A] 立即做 [B] 先列入计划 [C] 仅调研" |

`{X}`、`{Y}`、`{Z}`、`{计划 X}` 从轻量研究通的结果中填入。占位符值来自活跃计划、上下文路由关键词和近期 git 状态。

## 路由选定

Tier 响应完成后，匹配 `docs/process/routing.md` 中的路由表条件，直接产出最终路由。

## 快速模式判定

路由初步命中 `需求` 时，在进入 main.md 前检测是否满足快速模式条件：

| # | 条件 | 检测方法 |
|---|------|---------|
| 1 | 单模块 | 请求只涉及一个模块/包/文件 |
| 2 | 无架构影响 | 无新增服务、无 DB schema 变更、无 API 契约变更、无通信方式变更 |
| 3 | 方案唯一 | 不存在需要对比选型的方案决策（如"加字段""改校验""加缓存"） |
| 4 | AC 可快速验证 | 需求可描述为 ≤3 条可逐条测试的验收标准 |

全部命中 → 路由改为 `快速模式`，进入 [fast.md](flows/fast.md)。

任一不满足 → 保持 `需求` 路由，进入 [main.md](flows/main.md)。


## 澄清兜底

Tier 2 回答后仍无法确定路由时：

1. 一句话说明仍不清楚的地方
2. 问最后一个直接问题（非多选）
3. 仍无法解决 → 以最窄合理范围进入调研流程

最多两轮澄清。两轮后必须路由。
