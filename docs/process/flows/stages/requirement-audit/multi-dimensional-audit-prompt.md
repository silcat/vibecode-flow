# 多维度审计提示词

当普通的特定对象审计不够，且工作需要同时从多维度接受挑战时使用此提示词。

这是一个通用默认提示词。复制模板后，根据项目真实的所有者文档、保护区、验证技术栈、部署模型和已知风险领域进行调整。

```text
阅读 `AGENTS.md`、`docs/index.md`、活跃需求和所有者文档、相关计划或变更区域，以及最新验证或审计证据。

从多个维度审计工作，而非每次仅一个产物。

至少检查以下维度：
- 需求正确性
- 所有者文档对齐
- 架构或边界影响
- 验证充分性
- 回归风险
- 路由和技能选择正确性
- 计划注册表或自治策略偏移

不要假设模板默认维度对每个仓库都足够。当复制后的项目有受保护领域、集成密集型流程、安全敏感路径、受监管工作流或不寻常部署约束时，添加项目特定维度。

首先返回发现，按严重程度排序。
如果发现阻塞性问题，说 `需要修改` 并列出确切文件、维度和缺失证据。
如果没有阻塞性问题，说 `通过多维度审计` 并按维度列出残余风险。
```
