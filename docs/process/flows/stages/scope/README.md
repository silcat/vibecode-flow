# 范围判定

## 文件角色

根据需求文档和架构基线判定工作级别（轻量/单计划/多计划），决定后续阶段序列。

## 进入条件

requirement.md 存在。

## 执行步骤

### 1. 能力覆盖分析

对照 requirement.md 逐条验收标准，检查现有模块能力是否覆盖：
- `docs/baseline/architecture/module-boundaries.md` — 哪些模块涉及
- `docs/baseline/context/project-context.md` — 现有技术栈
- `docs/baseline/standards/` — 现有契约

能覆盖 → 标记已有模块。不能覆盖 → 标记为"能力缺口"，触发 research。

### 2. 范围判定

| 级别 | 条件 |
|------|------|
| 轻量 | 全部满足：单模块 + 不碰契约 + ≤3 文件 + 无风险 + 无能力缺口 |
| 单计划 | 碰以上任一条，但仍在单一模块内 |
| 多计划 | 可拆为多个独立交付的子工作 |

判定轻量时，须额外说明"为什么不需要完整流程"。证明不充分 → 默认升级为单计划。

## 产出物

| 产出 | 路径 |
|------|------|
| 范围判定 | `docs/work/<branch>/scope-analysis.md` |

文件格式：

```markdown
# 范围判定 — <branch>

## 涉及模块
- [模块1]

## 契约触碰
- [契约1] / 无

## 能力缺口

对照 requirement 验收标准，逐条检查现有模块是否覆盖。不能覆盖的归入以下四类：

| 类型 | 缺口描述 |
|------|---------|
| 新第三方库/框架 | [描述] |
| 新微服务 | [描述] |
| 新外部平台 | [描述] |
| 现有模块缺能力 | [描述] |

无缺口则写"无"。

## 预估变更文件数
[N]

## 轻量五条件
- 单模块：Y/N
- 不碰契约：Y/N
- ≤3文件：Y/N
- 无风险：Y/N
- 无能力缺口：Y/N

## 判定
轻量 / 单计划 / 多计划

## 判定理由
[如是轻量，说明为什么不需要完整流程]
```

`Test-Path docs/work/<branch>/scope-analysis.md` 确认文件存在。
