# 范围判定

## 文件角色

根据方案决策判定工作级别（轻量/单计划/多计划），决定后续阶段序列。判定基于独立交付能力，不基于机械指标。

## 进入条件

requirement.md、investigate.md、solution.md 存在。solution 阶段完成证明通过。

## 执行步骤

读取 solution.md 中选定方案的涉及模块、变更估算、新增依赖和架构影响。基于方案决策判定：

### 范围判定

| 级别 | 条件 | 说明 |
|------|------|------|
| 轻量 | 全部满足：单模块 + AC ≤ 3 + 无需方案决策 + 无架构影响 | 无需 plan.md，直接实施 |
| 单计划 | 不满足轻量条件，且无法拆为独立交付切片 | 一个 plan.md，可含多个顺序阶段 |
| 多计划 | 可拆为多个独立交付的切片 | 每个切片独立 plan.md，可并行 |

**判定原则：**

- 按独立可交付切片拆分，不按模块数量机械判定
- 一个计划 = 一个阶段（哪怕改动再小）。多阶段不一定需要多计划
- 判定轻量时需说明"为什么不需要完整流程"。证明不充分 → 升级为单计划

### 拆分规则

能否拆为多计划，不看模块数量，看依赖关系：

| 不能拆 | 可以拆 |
|--------|--------|
| 后段代码直接依赖前段代码的源文件（同一分支/PR 内） | 后段仅依赖前段的已部署接口（不同分支/PR） |

示例：
- Service A 改内部实现，Service B 需同步改调用代码 → 不能拆（B 依赖 A 的源文件）
- Service A 先部署新接口，Service B 通过 Feign/API 调用 → 可以拆（B 依赖已部署接口）

### 典型场景

| 场景 | 判定 | 理由 |
|------|------|------|
| 修单文件 bug | 轻量 | 单模块 + AC=1 + 无架构影响 |
| 单模块加小字段/接口 | 轻量 | 单模块 + AC ≤ 3 + 无契约变更 |
| 单模块大范围重构 | 单计划 | AC > 3 或碰架构影响 |
| 跨模块功能但必须一起交付 | 单计划 | 不可拆为独立交付切片 |
| 涉及 API 契约变更 | 单计划 | 碰架构影响 |
| 功能有前后端独立切片 | 多计划 | 后端接口部署后前端可独立交付 |
| 多个互不依赖的功能点 | 多计划 | 各自文件独立，无依赖 |

## 产出物

| 产出 | 路径 |
|------|------|
| 范围判定 | `docs/work/<branch>/scope-analysis.md` |

文件格式：

```markdown
# 范围判定 — <branch>

## 方案摘要
引用 solution.md 的决策结论：选定方案、涉及模块、变更估算。

## 轻量条件检查
- 单模块：Y/N
- AC ≤ 3 条：Y/N（AC 编号：[列出]）
- 无需方案决策：Y/N
- 无架构影响（无契约变更、无新增服务/DB、无通信方式变更）：Y/N

## 判定
轻量 / 单计划 / 多计划

## 判定理由
[说明为何此判定。轻量需证明不需要完整流程，证明不充分则升级为单计划。多计划需列出可拆为哪些独立切片（仅名称），切片编排由 project/plan 阶段负责。]
```

## 完成证明

`Test-Path docs/work/<branch>/scope-analysis.md` 确认文件存在。

## 完成报告

完成证明通过后，输出以下块：

```
**总结：** [1-2 句话总结本阶段产出]
**阻塞/顾虑：** [仅在有阻塞或顾虑时出现此字段]
**下一步：** 当前命中 [退出路由中的实际条件]，等待人类确认后进入 [对应去向]。
```

## 退出路由

完成证明通过后，等待人类确认才进入下一阶段。禁止自动推进。

| 条件 | 去向 |
|------|------|
| 判定 = 轻量 | → implement |
| 判定 = 单计划 | → requirement-audit |
| 判定 = 多计划 | → requirement-audit |
| 方案信息不足以判定 | → solution |
