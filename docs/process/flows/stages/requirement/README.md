# 合成需求

## 文件角色

将讨论记录与外部材料合成为结构化需求文档，验收标准逐条可独立测试。

## 进入条件

discussion.md 已就位，无未决阻塞问题。

## 执行步骤

按 `template.md` 填写需求文档。产出 `docs/work/<branch>/requirement.md`。

要求：
- 验收标准已编号，每条以"用户/系统可观察行为"开头（非实现细节）
- 每条验收标准已标注可验证方式（手动 / 单元测试 / 集成测试）
- 未决问题全部标记 `[未决]` 或 `[已解决]`
- 无 `[待定]` 或 `TBD` 占位符

## 产出物

| 产出 | 路径 |
|------|------|
| 需求文档 | `docs/work/<branch>/requirement.md` |

## 完成证明

在对话中输出自检：

```
::requirement-check
- AC 已编号：[N] 条
- 无 TBD/待定：✓ / ✗
- 可验证方式已标注：✓ / ✗（缺失项：[列出]）
```

## 退出路由

| 条件 | 去向 |
|------|------|
| 完成证明 PASS | → scope |
| 完成证明 FAIL | 回到自身修改 |
| 需求根本不合格 | → clarify |
