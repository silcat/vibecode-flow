# 流程定义

流程协议和阶段执行指南。稳定，不随业务变。

## 路由

- `intent-detect.md` — 意图检测 + Tier 响应（入口前）
- `routing.md` — 优先级路由表（入口）

## 阶段

目录名是全局唯一标识符，所有流程文件通过目录名引用阶段。中文名仅供人读。

| 目录 | 阶段 | 职责 |
|------|------|------|
| `collect` | 收集输入 | 收集原始输入材料 |
| `clarify` | 澄清模糊 | 条件触发，引导澄清 |
| `requirement` | 合成需求 | 写出 requirement.md |
| `scope` | 范围判定 | 判轻量/单计划/多计划 |
| `research` | 技术调研 | 条件触发，结构化选型 |
| `baseline` | 更新基线 | 条件触发，固化到基线 |
| `audit` | 需求与基线审计 | 审计需求→基线一致性 |
| `plan` | 编写计划 | 单计划（type: standalone） |
| `project` | 项目拆分 | 总计划 + 子计划骨架 + 编排入口（type: master） |
| `plan-audit` | 计划审计 | 审计计划可行性 |
| `implement` | 实施验证 | TDD 实施 |
| `closure` | 闭环审计 | 实施⇔计划闭环 |
| `log` | 日志回顾 | 每日日志 + 错误模式 |
| `skill` | 技能提取 | 条件触发，模式提升 |
