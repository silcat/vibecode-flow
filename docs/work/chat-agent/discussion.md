### 需求原始描述

> 想要实现一个企业级agent，按照功能优先级依次实现直到完整

- 类型：面向企业内部的 AI 助手（聊天、知识库问答、工具调用）
- 能力关键词：聊天、MCP、知识库（用户重复提及 MCP，强调工具集成）
- 策略：按功能优先级分阶段实现，渐进式完善
- 部署：先独立项目，后续可作为微服务接入 Spring Cloud 体系
- 技术栈上下文：当前项目为 Spring Cloud Alibaba 全家桶，但 agent 本身先独立开发

### Q1: 大模型选型
- AI: 决定核心依赖和成本模型
- 人类: D——抽象层设计，目前只需支持 DeepSeek
- 决议: 设计统一的 LLM 抽象接口，首期对接 DeepSeek API，后续可插拔扩展

### Q2: 前端形态
- AI: 决定交互层的技术选型
- 人类: 聊天界面（Web UI）
- 决议: 独立 Web 聊天界面

### Q3: MCP 具体场景
- AI: 决定 agent 工具能力边界
- 人类: D——先做框架支持 MCP 协议，具体工具边走边加
- 决议: 实现标准 MCP 客户端，支持用户自行配置 MCP Server 接入

### Q4: 知识库定位

- 人类: A——先做文档问答，B 后续作为 MCP 场景接入
- 决议: 首期实现 RAG 文档问答（向量存储 + Embedding + 检索）

### Q5: 企业级含义
- AI: 多租户 / 权限审计 / 高可用
- 人类: D——以上都要，但目前不优先，先实现 agent 核心功能
- 决议: 企业级特性（多租户、审计、高可用）后期追加，首期聚焦核心 agent 能力
