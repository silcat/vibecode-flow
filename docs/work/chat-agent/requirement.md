# chat-agent 需求

## 范围内

构建一个企业级 AI 聊天 agent，具备以下核心能力：

1. **对话** — 基于 LLM 的自然语言对话，支持多轮上下文
2. **知识库（RAG）** — 文档上传 → 向量化 → 检索增强生成，支持 PDF/Word/Markdown
3. **MCP 工具调用** — 标准 MCP 客户端，用户可配置外部 MCP Server，agent 自主调用工具

按功能优先级渐进实现：对话 → 知识库 → MCP。

## 范围外

- 多租户、权限审计、高可用（后期追加，非首期）
- 结构化数据库/API 直查（后续作为 MCP 场景自然接入）
- 接入 Spring Cloud 微服务体系（先独立运行）
- 除 DeepSeek 外的其他 LLM 适配（抽象层预留，不实现）

## 用户可见行为

### 对话
- 用户在 Web 聊天界面输入消息 → agent 调用 DeepSeek 生成回复 → 流式展示
- 支持多轮对话上下文记忆（同一会话内）
- 支持新建/切换/删除会话

### 知识库
- 用户上传文档 → 系统解析、分块、向量化存储 → 提示处理完成
- 用户提问时 → 系统检索相关知识片段 → 注入 LLM 上下文 → 生成带来源引用的回答
- 支持管理已上传文档（列表查看、删除）

### MCP
- 用户在配置界面添加 MCP Server 连接信息 → agent 启动时加载工具列表
- 对话中 agent 判断需要调用工具 → 执行 MCP 工具调用 → 将结果注入对话上下文

## 数据与规则

- 会话数据：对话历史、会话元信息
- 知识库数据：原始文档、分块文本、向量嵌入
- MCP 配置：Server 地址、认证信息
- LLM 抽象层：统一接口，首期仅实现 DeepSeek adapter

## 未决问题

- 无。全部已澄清并决议。

## 验收标准

### 对话
1. 用户发送消息 → 3 秒内开始流式返回 LLM 回复
2. 同一会话内连续对话 → LLM 能引用上文内容
3. 创建新会话 → 上下文隔离，旧会话历史可回看

### 知识库
4. 上传一份 PDF → 系统解析并向量化存储 → 提示成功
5. 针对已上传文档内容提问 → 回复包含文档中相关信息并标注来源
6. 删除已上传文档 → 相关知识条目不可再被检索

### MCP
7. 配置一个有效的 MCP Server → agent 启动后工具列表中可见该 Server 提供的工具
8. 对话中触发工具调用 → agent 正确调用工具并将结果用于回复生成
