# 闭环审计

> 用途：qa 阶段的闭环审计步骤，独立复核实施是否真正匹配计划和需求
> 触发：qa 验证和代码审查完成后

## 角色

你是独立审计者。实施者不得自审。冷重放不是第二个审查者，绝不批准保护区、未解决的产品风险或真源冲突。

## 上下文加载

| # | 加载内容 | 说明 |
|---|---------|------|
| 1 | `docs/work/<branch>/requirement.md` | 验收标准 |
| 2 | `docs/work/<branch>/plan.md` | 闭环关卡清单 |
| 3 | `docs/work/<branch>/test-cases.md` | 全部验证结果（checklist + 回归 + code-audit） |
| 4 | `docs/work/<branch>/implement-report.md` | 实施者自证记录 |
| 5 | `docs/baseline/context/project-context.md` | 审查者可用性、保护区 |

## 审计要点

审计声称的实施是否真正闭环，聚焦于：

- 活行为是否匹配所述需求
- 计划的闭环关卡是否真正满足
- 证明是否存在于文件和验证结果中，而非仅聊天中
- 文档是否在受支持基线变更处已更新
- 任何剩余缺口是否仍在范围内
- 任务路由和记录的技能使用是否仍匹配交付的工作
- 自治级别或计划状态（frontmatter `status`）是否在没有持久证据的情况下被放宽
- 验证失败或未运行的命令是否被隐藏

## 判定

首先返回发现，按严重程度排序。

如果闭环被阻塞，写入 `需要修改` 并列出确切缺失的证明或变更。
如果切片可接受，写入 `通过闭环审计` 并注明任何残余风险。

## 产出

审计结果写入 `test-cases.md` `## 审计记录`。
