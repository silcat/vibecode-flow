# 验证检查清单

> 用途：阶段 ? 出口逐条打勾 + 阶段 ? 闭环审计入口核对
> 触发：所有实施任务（有计划路径和无计划路径均使用）

## 如何执行

逐条执行以下检查项。每条通过打勾，未通过记录发现并阻断继续。

## 检查项

### 编译与类型
- [ ] 类型检查/编译零错误
- [ ] Lint/静态分析零新增告警

### 单元与集成
- [ ] 单元测试全绿
- [ ] 集成测试全绿（含数据库/外部服务 mock）
- [ ] 新增代码路径有对应测试覆盖

### API 与契约
- [ ] API 响应状态码与关键字段与需求一致
- [ ] 如有契约变更，已在对应文档（`docs/baseline/architecture/`）中反映

### 数据库
- [ ] 迁移脚本正向执行成功
- [ ] 迁移脚本可回滚（如适用）
- [ ] 数据完整性约束未被破坏

### 回归
- [ ] 从已验证的表面中选最小代表性检查点重跑
- [ ] 回归发现已分类处理（修复 / 记录到 `docs/bugs/` / 创建 followup 计划）

### 运行态
- [ ] 应用启动无异常日志
- [ ] 关键业务流程手动验证通过

### 证据
- [ ] 所有验证命令实际执行过，输出已捕获
- [ ] 无占位符命令被当作验证通过

## 退出条件

- 所有适用检查项打勾
- 未通过的检查项已记录为阻塞或非阻塞后续

## 适用范围

- 有计划路径：阶段 ? 出口强制使用；阶段 ? 闭环审计核对打勾完整性
- 无计划路径：阶段 ? 出口强制使用
- 表层 Bug 修复：跳过数据库/迁移相关条目
