# grill-with-docs

对需求或计划进行逐项追问澄清，对照已有文档和代码基线，在术语统一、边界明确后才进入下一阶段。

## 何时使用

- 进入阶段 ② 澄清模糊（`docs/process/routing.md`）
- 源材料不完整、存在矛盾、多种解读合理时

## 逐个追问协议

一次只问一个问题。等待用户回答后再继续下一个。每个问题附带 AI 的推荐答案。

格式：

```
Q: [问题]
A: [推荐答案]（附理由）

等待确认...
```

如果问题可以通过探索代码库回答，**探索代码库而不是提问**。

## 四个检查维度

### 1. 术语挑战

当用户使用的术语与 `docs/baseline/context/glossary.md` 中已定义术语冲突时，立即指出。

例子："你的文档里定义取消为订单级操作，但你刚才说的似乎是行级取消"

### 2. 精炼模糊语言

当用户使用模糊或过载术语时，提出精确定义。

例子："你说账户——是指 Customer 还是 User？两者是不同的实体。"

### 3. 场景压测

当讨论领域关系时，编造具体场景来压测边界。

例子："如果一个订单包含 3 个商品，用户想取消其中 2 个——这算部分取消吗？"

### 4. 代码交叉验证

当用户声称某功能按某种方式工作时，检查代码是否真的那样工作。发现矛盾时当场指出。

例子："你的代码里整单取消是 Order.cancel()，但你现在说支持部分取消——代码不支持，哪个是对的？"

## 写入位置

| 内容 | 写入哪里 | 何时写 |
|------|---------|--------|
| 讨论过程（问答记录） | `docs/work/<branch>/discussion.md` | 每次有实质性决议后追加 |
| 确定的术语 | `docs/baseline/context/glossary.md` | 术语决议后立即写入 |

讨论文件懒加载：有内容才创建，不创建空占位符。


## 退出条件

当以下全部满足时，阶段 ② 完成：
- 术语统一、无歧义
- 每个分歧点已有明确决议
- 阻塞性问题已解除或标记为待确认
- 讨论记录已写入 `docs/work/<branch>/discussion.md`
- 术语决议已写入 `docs/baseline/context/glossary.md`
