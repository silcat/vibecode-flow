# 技能编写提示词

当需要创建新的可复用技能（提示词模板）并将其注册到 `docs/skills/README.md` 时使用此技能。

此技能本身不替代需求、设计或架构文档——它是方法选择器，指导 AI 如何正确地生成符合项目规范的新技能文件。

## 何时使用

- 相同工作方法模式已重复出现，值得固化
- 已确认问题不是路由缺失或所有者文档不清晰导致的
- 外部引入了纯方法类 skill，需要转换成 AGE 格式
- 现有技能的 README 注册表需要新增条目

## 何时不使用

- 问题可以通过修正路由、澄清所有者文档或补充计划指导来解决
- 内容是领域知识（框架最佳实践、业务规则）——这些应进 `docs/references/` 或 `docs/baseline/architecture/`
- 模式尚未稳定，仅出现过一两次
- 工作只是局部低风险的一次性编辑

## 所需输入

- 触发技能创建的重复问题描述或外部 skill 源材料
- 相关所有者文档（确认这不是知识缺口）
- 项目的真实验证命令、命名约定和技术栈（来自 `docs/baseline/context/project-context.md`）

## 执行模式

### 1. 前置检查：确认技能真的是答案

在创建新技能之前，依次排除：

- **路由缺失？** — 检查 `AGENTS.md` 和 `docs/index.md` 是否已经能正确路由该任务类型
- **所有者文档缺失？** — 如果缺少的是业务规则或架构约束，应补充 `docs/baseline/architecture/` 或 `docs/baseline/standards/`，而非创建技能
- **计划指导缺失？** — 如果问题出在执行流程上，先检查 `docs/work/<分支>/00-plan-authoring-and-execution-guide.md`

仅当以上三者都不是根因时，才继续创建技能。

### 2. 选择技能格式

**格式 A：结构化指南**（有"何时使用""何时不使用""所需输入""执行模式""输出"等章节）

适用于 AI 自己直接阅读并遵循的技能。使用场景：
- 任务执行类技能（如 bug-diagnosis-prompt.md）
- AI 需要按步骤决策的工作方法

**格式 B：内联提示词块**（标题 + 一句话描述 + ` ```text ` 包裹的提示词正文）

适用于需要喂给独立子代理或审查者的技能。使用场景：
- 审计类技能（如 plan-audit-prompt.md、closure-audit-prompt.md）
- 需要一个干净会话上下文执行的审查任务

### 3. 编写技能文件

无论哪种格式，技能文件必须包含：

- **标题**：以 `# ` 开头，简短命名（如"计划审计提示词""Bug 诊断提示词"）
- **用途说明**：一句或一段话说明该技能解决什么问题
- **技能正文**：格式 A 用章节组织，格式 B 用 ` ```text ` 包裹

技能正文中：
- 引用项目真实文件路径（从 `docs/baseline/context/project-context.md` 获取验证命令，从 `docs/index.md` 获取路由）
- 引用项目真实的所有者文档
- 不要写入虚构的外部引用
- 不要写入具体的业务规则（那是所有者文档的职责）

### 4. 定制——替换通用占位符

如果技能来自外部或模板，必须根据项目真实情况定制：

- 文件路径 → 替换为项目真实路径
- 验证命令 → 使用 `docs/baseline/context/project-context.md` 中的真实命令
- 技术栈名称 → 替换为项目实际使用的技术
- 命名约定 → 对齐项目的真实约定
- 保护区引用 → 对齐 `docs/baseline/context/project-context.md` 的真实保护区表

### 5. 注册到技能索引

在 `docs/skills/README.md` 的注册表中添加一行，填满五列：

| 技能 | 何时使用 | 何时不使用 | 所需输入 | 预期输出 |

规则：
- "何时不使用"必须诚实填写——如果填不出清晰的排除条件，说明技能边界模糊，先不要注册
- "所需输入"必须是项目中真实存在的文件或可获取的信息
- "预期输出"应描述具体产物，而非模糊的"更好的代码"

### 6. 可选：更新起始技能列表

如果新技能是高频入口，在 `docs/skills/README.md` 的"起始技能"部分添加其文件名。

## 输出

- 新创建的 `docs/skills/<技能名>.md` 文件
- 更新后的 `docs/skills/README.md`（注册表新增一行）

## 反模式——避免以下做法

- **为每个业务场景创建技能** — "用户注册 skill""订单管理 skill" 等应作为所有者文档存在于 `docs/baseline/architecture/` 或 `docs/baseline/standards/`
- **复制外部 skill 时不定制** — 直接粘贴会导致引用不存在的文件路径和命令
- **跳过后置检查直接注册** — 不确定技能是否真正需要时，先在 `docs/work/<分支>/` 中讨论
- **技能正文写成了教程** — 技能是给 AI 代理执行的指令，不是给人类阅读的知识文档
