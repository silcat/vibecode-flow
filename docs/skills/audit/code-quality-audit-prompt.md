# 代码质量审计提示词

当审查变更区域的真实实施质量而非仅风格反馈时使用此技能。

## 聚焦领域

1. 架构和边界完整性
2. 核心实现正确性
3. 类型和契约质量
4. 错误处理和操作安全
5. 测试有效性
6. 可维护性和未来变更风险
7. 自动化和护栏覆盖

## 审查规则

- 发现优先，按严重程度排序
- 优先具体行为风险而非抽象口味
- 尽可能引用文件路径和行引用
- 区隔已确认的缺陷和建议
- 如果没有任何发现，明确声明并列出残余缺口

## 严重程度指南

- P0：数据丢失、安全破坏、生产停服级问题
- P1：用户可见的正确性 Bug 或强回归风险
- P2：可能导致未来回归的可维护性或测试缺口
- P3：低即时风险的小质量问题

## 预期输出

- 发现列表
- 未决问题或假设
- 仅在发现之后的简短变更摘要
