# 索引路由审计提示词

在审计文档目录的索引结构是否达到其路由目标时使用此提示词。

典型触发条件：

- 新建或重组了文档树
- 现有索引已过时或与所指向的文件不一致
- 代理或人类反复无法通过索引找到正确文档
- 将本模板复制到新项目前，验证复制的索引仍路由正确

## 审计提示词

```text
你正在审计一个文档索引结构的路由有效性。

## 第 1 步 — 阅读索引

阅读顶层索引文件（如 `INDEX.md` 或 `docs/index.md`）及其链接到的每个子索引或 README。

对每个索引条目，记录：
- 所述目的或任务场景
- 指向的路径
- 目标文件是否存在及其内容是否大致匹配所述目的

返回一个覆盖表，列：| 条目 | 所述目的 | 目标路径 | 存在 | 匹配目的 | 备注 |

标记任何以下条目：
- 目标文件不存在
- 目标存在但其内容不匹配所述目的
- 所述目的太模糊，读者无法判断是否相关
- 多个条目指向同一目标但描述不同
- 应被索引的现有文档缺失于索引中

## 第 2 步 — 基于角色的路由测试

对以下每个角色，模拟一个现实的信息需求，然后追踪从索引到答案的最短路径。记录该角色是否成功及需要多少跳。

角色 A — 加入项目的新开发者：
- 需求："如何设置我的开发环境并运行项目？"
- 需求："[主要功能区域]的代码在哪里？"

角色 B — 启动非平凡任务的 AI 代理：
- 需求："在编写代码之前我必须遵循哪些当前规则？"
- 需求："在哪里找到[技术领域]的所有者文档？"

角色 C — 审计已完成切片的审查者：
- 需求："当前工作的计划在哪里，其闭环关卡是什么？"
- 需求："最近的实施日志在哪里？"

角色 D — 更新文档的维护者：
- 需求："更新索引 vs 添加新文档的规则是什么？"
- 需求："哪些文档已知为过时或低置信度？"

对每个角色需求，返回：
| 角色 | 需求 | 起点 | 跳数 | 找到 | 路径 | 问题 |

如果角色无法仅通过索引到达答案，记录失败点和缺失的内容。

## 第 3 步 — 结构质量检查

检查：
- 孤儿文件：目录树中无法从任何索引入口到达的文件
- 过时引用：指向已移动、重命名或删除文件的索引条目
- 深度不均衡：从顶层索引到达可操作内容需要超过 3 跳的路径
- 重复：相同规则或知识在多个索引文件中陈述而无交叉引用
- 类别混淆：文档内容属于索引所指定的不同目录
- 缺失中间索引：文件数量超过 ~10 但缺少自身 README 或目录的目录

## 第 4 步 — 返回发现

按严重程度排序返回发现：

对每个发现包含：
- 标题
- 受影响的索引入口或文件路径
- 当前缺口
- 对路由有效性的影响
- 建议

如果没有任何发现，明确说明并列出残余风险。
```

## 定制说明

将本模板复制到真实项目后：

- 将角色需求替换为匹配项目领域和常见任务类型的现实问题。
- 添加项目特定的结构规则（如最大索引深度、文件数超 N 的目录需有子索引）。
- 如果项目使用分层索引模式（摘要目录 → 分类目录 → 单个文档），添加检查每层大小和粒度是否适当。
- 根据项目实际文档深度调整跳数阈值。
